# Release validation

## Verified in this workspace

See the latest CTest output and dist package generated by scripts/build.ps1. Automated tests cover settings round trips, bounds, missing settings and malformed JSON. They do not establish hardware compatibility.

Sensor validation on 4 November 2026: Intel Core i5-13420H and Intel UHD Graphics, standard-user session. Direct LibreHardwareMonitor enumeration returned CPU loads and GPU D3D engine values. The native HardwareMonitor probe loaded the managed bridge and returned GPU utilization through Windows GPU Engine counters. With sensor DLLs absent, the native probe still returned GPU load and reported the missing bridge (Windows error 126), then exited successfully. Temperature readings were unavailable in this session; elevated temperature access has not been validated. GPU aggregation regressions cover process contexts, separate adapters, invalid data and clamping.

## Required before claiming broad compatibility

- Clean Windows 10 x64 and Windows 11 x64: extract ZIP, run as standard user without developer tools; exercise missing sensor DLLs and unavailable sensors.
- Intel/AMD CPUs; Intel/AMD/NVIDIA GPUs; desktop without battery and laptop on AC/battery. Confirm unavailable sensor states and dependency requirements.
- DPI 100%, 150%, 200%; mixed-DPI monitors, negative monitor coordinates, docking and display-driver restart.
- Explorer restart, taskbar auto-hide, fullscreen games, sleep/resume, lock/unlock and sign-out.
- Ethernet/Wi-Fi changes, VPN, offline start, adapter removal and reconnection. Check throughput against a known transfer.
- Install/upgrade from a path containing spaces and Unicode; read-only executable folder; corrupt configuration; autostart after moving a portable folder.
- Measure idle CPU, private bytes, handles and UI responsiveness with dashboard open/closed over at least 30 minutes and after repeated open/close cycles. Record Windows build, hardware, polling interval and sensor availability.
- Review third-party bridge/managed-library licenses, driver safety, and redistribution rights. Inspect staged EXE/DLL dependency lists on a clean VM.
- Authenticode signing, antivirus checks, versioning, release checksums and documented rollback.

The current release is x64 only. Do not advertise native ARM64 or 32-bit support, universal temperatures, zero dependencies, or measured resource budgets without validation.

- Release build and native tests cover fixed metric positions, white labels with dynamic value colours, separate daily/monthly accounting, history persistence/CSV export, GPU adapter selection, settings migration/draft merges, and native daily-usage tooltip registration/update/destruction. The tooltip test uses the same common-controls v6 application manifest as the shipped executable.

- The installed executable was launched through its per-user Windows logon task: Highest privileges, Interactive token, 15-second logon delay, no password, battery start allowed, battery stop disabled, and no execution time limit. A physical laptop reboot was not performed.
- Elevated native sensor report returned CPU 48.97 C and GPU 42 C on this machine; GPU load was read through Windows counters and the active adapter identified as dGPU.

These are local short-sample observations, not universal budgets or battery-life measurements. The managed sensor provider contributes to the memory footprint.
- Settings are rendered only on demand or at the telemetry interval for visible Overview/Data usage pages. There are no continuous UI animations. Hardware initialization/sampling uses a worker thread and battery rate queries are throttled.

## Version 1.2.2 checks

The context menu is reduced to Settings, daily/monthly usage and a confirmed Exit action. A native menu regression checks the exact actions and verifies that quick visibility/startup toggles are absent. Click callbacks use Show rather than Toggle for the dashboard. Default fullscreen hiding is disabled and legacy hidden display mode migrates to taskbar mode.

Default update interval is two seconds; hardware requests follow this interval, battery rate enumeration remains throttled, and duplicate managed GPU polling is avoided when native NVIDIA temperature is available. Startup retries abnormal process failures at one-minute intervals, at most three times. A normal Exit completes successfully and does not trigger retries. RAM savings are hardware/provider dependent; CPU temperature support retains a managed-runtime cost.

Installed and launched version 1.2.2 on 5 November 2026 after a normal exit of the old process. The installed EXE hash matches the tested Release build. All six CTest suites passed. The running app responds and checkpoints usage history. Its startup task is running with Highest privileges, an interactive logon trigger delayed 15 seconds, battery execution allowed, no time limit, and three one-minute failure retries.
